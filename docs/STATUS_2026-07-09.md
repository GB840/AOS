## 二、本次修复（commit `5c88d2c`）

### 1. 恢复访问
AOS 进程僵死（端口占着但不响应）+ 系统中多个 AOS 实例竞争 8000 端口。清理旧实例、用正确环境重启，访问恢复。

### 2. Hermes 三重失效（之前误判"Hermes 真在跑"，实际每次 L1 都回落云端）
- **非法参数**：`Hermes.chat()` 被传入 `session_id=`，但真实 `AIAgent.chat(message)` 不接受 → `TypeError` 回落。
- **返回类型**：真实 `AIAgent.chat()` 返回 **str**，旧代码当 dict 用（`result.get("response")` / `result["level"]=`）→ 回落。
- **包名撞车**：`from utils import safe_json_loads` 被 `D:/AOS/src/utils`（空包）遮挡 Hermes 的 `utils.py` → `ImportError` 回落。
- **修复**：去掉 `session_id` + 适配 str 返回 + 在 `src/utils/__init__.py` 重导出 Hermes 的 utils 符号。
- **效果**：`/api/chat` L1 现在返回 `backend=hermes, channel="Hermes直接对话"` —— **Hermes 真正生效**。

### 3. config.py .env 注入真正落地（P1-4 补完）
之前 P1-4 写的 `.env` 注入代码实际没进文件。本轮补在 `Config()` 构造之前（双写无前缀 + `AOS_` 前缀）。
**效果**：重启时**未手动 export 任何 key**，Mem0 仍是 `mem0(real)` —— 换启动方式不再静默降级。

## 五、手动拉起命令（如需）

```bash
cd /d/AOS
AOS_DIR=D:/AOS
VENV_PY="$USERPROFILE/.workbuddy/binaries/python/envs/aos/Scripts/python.exe"
# 1) 清掉占用 8000 的旧实例

# 2) 启动（PYTHONPATH 必须含 src；AOS_EXTRA_SITE 指向装了 mem0/langfuse 的 default venv）
export AOS_DIR PYTHONPATH="D:/AOS/src;D:/AOS" \
  AOS_EXTRA_SITE="$USERPROFILE/.workbuddy/binaries/python/envs/default/Lib/site-packages" \
  AOS_API_BASE="http://127.0.0.1:8000"
nohup "$VENV_PY" -u -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000 --log-level info > aos_live.log 2>&1 & disown
```

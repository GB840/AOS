**验真（防假货）**：三个新适配器均真实现——
- `CodeExecutionAdapter`：用真实 `execution.sandbox.SandboxManager` 起沙箱、提取 ```` ```python ```` 代码块执行、返回 stdout/stderr（SandboxManager 已核实存在，`create_sandbox`/`execute_code` 真有）
- `FileAdapter`：workspace 限定 + `..`/绝对路径遍历防护 + 诚实失败
- `WebFetchAdapter`：stdlib `urllib` 零依赖抓取 + 简易 HTML 剥离，失败如实返回

**🔴 真实断点（提交前必修）**：
`build_default_kernel()`（`src/kernel/wiring.py:89`）内部**不调 `build_fabric_hub`**，`kernel.fabric_hub` 默认 `None`。于是：
- `POST /api/v1/chat`（自动检测命中 task）→ `v5_bridge.run_task` → `self.kernel.fabric_hub` 是 `None` → 返回 **"fabric 能力枢纽未挂载"**
- `POST /api/v1/run_task` → 同上，断
- 只有 `scripts/aos.py task` 能跑（它自己 `build_fabric_hub(isolate_heavy=False)` 绕过 kernel）

**结论**：CLI 路径可用，API 路径断。这 564 行若现在提交，等于把半残功能合进去。
